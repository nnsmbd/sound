# VolumeMixer

Нативная menu bar утилита: громкость отдельных аудиоприложений, mute и текущий системный выход. Swift/AppKit + C/Core Audio. Без webview, внешних пакетов, записи аудио, сети и устанавливаемого HAL-драйвера.

## Запуск

Открыть `../VolumeMixer.app`. В строке меню появится иконка регуляторов. Включить звук в приложении, открыть панель и изменить уровень. При первом захвате macOS запрашивает разрешение записи системного аудио. Его нужно предоставить самому пользователю. Меню шестерёнки открывает соответствующий раздел системных настроек.

100% означает исходный уровень приложения, 0% — тишину. Отдельная кнопка mute сохраняет выставленный уровень. «Вернуть исходную громкость» удаляет все активные тракты. Завершение приложения также прекращает обработку.

## Сборка

Требуется Swift 6 и macOS SDK 26 (для сборки Liquid Glass). Минимальная ОС приложения — macOS 14.4. На macOS 26 используется `NSGlassEffectView`, на предыдущих версиях — `NSVisualEffectView`. Внешний вид стекла определяется системой и настройками доступности; изображение — художественный ориентир.

```sh
zsh scripts/build.sh
zsh scripts/test.sh
```

Сборка подписана локальной ad-hoc подписью. Developer ID/notarization для распространения ещё не настроены. Пересборка может потребовать повторного предоставления разрешения macOS. Это локальная первая версия, а не готовый дистрибутив для других Mac.

## Архитектура

- `Audio.swift`: Core Audio discovery, группировка по реальному пути родительского .app, один private process tap + private aggregate на изменённое приложение.
- `AudioDSP.c`: Float32 stereo, interleaved/noninterleaved, 10 ms ramp, lock-free передача gain и диагностических счётчиков. Нет выделения памяти или Swift/ObjC в callback.
- `Coordinator.swift`: последовательный жизненный цикл, проверка устройств/процессов и callback health раз в секунду; при ошибке освобождает тракт и возвращает 100%.
- `Panel.swift`: AppKit-панель шириной 224 pt, настоящие иконки установленных приложений, NSSlider, VoiceOver labels, системный Liquid Glass.

Исходный звук подавляется только во время чтения tap (`mutedWhenTapped`). 100% без mute обходит обработку полностью. Системный default output не изменяется. Другие приложения не включаются в tap. При sleep освобождаются все тракты, после wake восстанавливаются.

Поддержка ограничена стереоустройствами с Float32 virtual streams. Многоканальные, mono hands-free, DRM, AirPlay и некоторые Bluetooth режимы не объявляются поддержанными. Переключение устройства пересоздаёт тракт и может давать короткий разрыв. Точная задержка и поведение после зависания процесса требуют аппаратной проверки. Хранение уровней между перезапусками не реализовано.

## Проверка разработчиком

```sh
../VolumeMixer.app/Contents/MacOS/VolumeMixer --diagnose
open ../VolumeMixer.app --args --preview
```

`--preview` явно помечен «макет», использует демонстрационные строки и не меняет настоящий звук. В обычном режиме список только реальный. `--check-route <key из --diagnose>` запускает ограниченную шестисекундную проверку на 30% с выводом счётчиков/пиков, без записи samples. Этот режим требует того же системного разрешения.
